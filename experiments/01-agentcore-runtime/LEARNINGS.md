# Learnings — Experiment 01

Status: PASS

## Hypothesis

A minimal direct-code AgentCore Runtime using IAM/SigV4 can prove the hosting/invocation boundary without the full sample stack.

## Verified before deployment

- `AWS::BedrockAgentCore::Runtime` is available in the LAB region.
- Live AWS readback showed zero existing AgentCore Runtimes before this experiment.
- AgentCore supports direct-code Python ZIP deployment from S3.
- IAM/SigV4 is a supported inbound authentication mechanism.
- The HTTP contract requires `POST /invocations` and `GET /ping` on port 8080.

## Live proof

The final deployment used:

```text
standard Python source
  -> standard ZIP archive
  -> dedicated S3 artifact
  -> AgentCore direct-code Runtime (Python 3.13)
  -> HTTP protocol
  -> IAM/SigV4 InvokeAgentRuntime
```

Provider verification showed:

- Runtime reached `READY`;
- artifact type was direct-code `codeConfiguration`, not a container image;
- runtime language was Python 3.13;
- entry point was `main.py`;
- protocol was HTTP;
- no custom authorizer was configured, so IAM/SigV4 was used;
- one invocation returned HTTP 200 with the expected deterministic `AgentCore Runtime OK` response;
- Runtime logs showed the server started on port 8080, the invocation returned 200, and AgentCore health checks reached `/ping` successfully.

## Packaging lesson

AgentCore validates ZIP format more strictly than a generic ZIP reader. Two hand-built ZIP attempts were rejected with `unsupported features or compression methods`. A normal archive generated by the standard `zip` utility passed immediately.

For reproducibility, `scripts/package.py` uses Python's standard `zipfile` implementation. Do not hand-craft ZIP binary structures for AgentCore direct-code deployment.

## Scope result

Not required for this proof:

- Cognito/JWT;
- React/CloudFront;
- ECR;
- CodeBuild;
- Lambda build waiter;
- VPC/network resources;
- Bedrock model invocation;
- long-lived AWS credentials.

A temporary branch-scoped GitHub OIDC role was used only to upload a standards-generated ZIP after the controller sandbox could not create one. It was deleted before completion and was never part of the retained architecture.

## Cleanup proof

After invocation:

- the runtime session was stopped;
- the successful Runtime was deleted;
- failed-create Runtime records were already deleted;
- the dedicated artifact object/bucket was deleted;
- the dedicated Runtime execution role was deleted;
- the temporary package-upload OIDC role was deleted;
- all experiment-owned Runtime log groups were deleted;
- final readback found zero experiment Runtimes and no retained experiment resources.

The pre-existing Terraform/OIDC state bucket, role, and SSM parameter were not modified.

## Decision

- AgentCore Runtime: **KEEP** — the managed Runtime boundary is useful and independently testable.
- Direct-code deployment: **KEEP** — materially simpler than the full ECR/CodeBuild sample for small Python experiments.
- IAM/SigV4 inbound auth: **KEEP** — best first authentication mode for AWS-internal/lab callers; Cognito/JWT should be added only when a browser/end-user path is actually required.

## Recommended next milestone

Test **AgentCore Gateway + Policy ALLOW/DENY** in isolation, using one harmless read-only tool and proving that `DENY` causes zero provider execution. This is more valuable to the SecCop governance question than adding a frontend now.
